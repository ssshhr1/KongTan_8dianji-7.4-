# 三段蛇骨机器人：Copley 八轴 + Mega 2560 / DM542 进给

本目录是独立的新版本；原八轴项目和 `KongTan_9Axis_Linkage_20260916` 保留。新程序使用上位机统一调度两条通信链路：PC → Ixxat/CAN → Copley 1～8；PC → USB-B/USB-A → Mega 2560 → PUL/DIR/ENA → DM542。Mega 不直接接入 Copley CAN，不把 DM542 当作 CAN 节点。

## 运行入口

- 上位机：`x64/Release/KongTan_9Axis_Arduino.exe`。
- Visual Studio 工程：`KongTan_8dianji.sln`，选择 x64；也可运行 `build.ps1 -Configuration Release -Test`。
- Mega 固件：`firmware/FeedAxis/FeedAxis.ino`，同目录包含 `BoardConfig.h`、`FeedCore.h`，一起保留。
- 配置：编辑 EXE 同目录的 `machine.ini`。工程根目录文件仅在输出目录尚无配置时复制，重新构建不会覆盖现场配置。
- 现有 PC 仍需对应 Ixxat VCI 驱动和 Visual C++/MFC x64 运行库。

启动程序不会自动连接、使能或运动。本次未执行任何实机连接或烧录。

## 电机分组与方向

| 电机 | 绳索/段 | 正向动作的成对收放 |
|---|---|---|
| 1 / 2 | 末端：上 / 下 | 上：1 收、2 放；下反向 |
| 3 / 4 | 末端：左 / 右 | 左：3 收、4 放；右反向 |
| 5 / 6 | 中段：上 / 下 | 上：5 收、6 放；下反向 |
| 7 / 8 | 基段：上 / 下 | 上：7 收、8 放；下反向 |
| 逻辑轴 9 | DM542 进给 | 正值进入，负值退回 |

`Axis1`～`Axis8` 的 `PullSign` 表示收绳对应编码器计数的符号，必须逐轴标定。默认 +1 仅为待确认值。界面机器人位移是电机编码器 counts，不是弯曲角度、绳长毫米或末端空间坐标。成对等 counts 收放还要求对应传动换算匹配。

旧程序中段按钮中的 2.5、3、1.5/1.1 等经验补偿和旧逆解没有用于新三段界面。新版本提供明确的分组点动和四组弯曲增量 + 进给的联动；跨段绳索耦合、张力和末端路径精度仍需机构标定，未声称已完成三段全模型逆解。

## 首次使用前的必要配置

1. **确认实物接线**：断电后逐条测量 DM542 的 PUL、DIR、ENA 到 Mega 的实际路径、有效电平和电气接口。用户已确认 Mega 2560 和 USB-B—USB-A，尚未确认引脚；此包不指定或猜测 D2/D8/D9 等实物接线。
2. 在 `BoardConfig.h` 中填写三个独立引脚、有效电平、脉冲宽度和方向建立时间。核实后将 `WIRING_CONFIRMED` 改为 `true`。当前为 false、引脚为 -1，固件不会配置运动引脚或输出脉冲，PC 也会拒绝使能。
3. Arduino IDE 选择 Mega 2560 / ATmega2560，编译并在确认实际串口后上传。上传前保证驱动器不能带动机构；本次没有替用户上传。固件使用 Arduino 核心 API，不依赖额外电机库。
4. 在 Windows 设备管理器确定 COM 号，填入 EXE 旁配置的 `[Arduino] Port`。115200 baud、8N1 已在两端统一。
5. 标定 `StepsPerMm`：用实际 DM542 细分设置、机械传动比和丝杆导程/传动行程计算初值，再以实测移动距离核对。当前值 0 会阻止连接，未填入假定脉冲数。
6. 填写每个 Copley 轴的绝对编码器软限位 `NegativeCounts/PositiveCounts`，并确认 `PullSign`。各轴初始限位都是 0，无法通过配置验证。
7. 填写进给轴相对**本次连接位置**的允许行程 `NegativeMmFromConnection` 和 `PositiveMmFromConnection`。每次连接的 H 握手把进给软件坐标记为 0；这不是物理寻零，重新连接前必须根据实际位置重新核实两侧余量。机器人仍使用 Copley 绝对编码器坐标。
8. 核实所有参数后，设置 `[Machine] Confirmed=1`，再点击“连接并使能九轴”。初次连接时等 USB 复位约 2 秒，然后读取位置、设置限位、逐轴使能；失败会尝试撤销所有轴。

ENA 撤销只在已确认电平和接线正确时有效。现场硬件停止回路应同时停止机器人驱动器和进给轴；软件无法替代硬件停止，也无法确认 DM542 的失步、接线或实际使能状态。

## 低速联动怎样工作

“执行九轴分段联动”输入末端上下、末端左右、中段上下、基段上下四个 counts 增量和进给 mm 增量。正负方向见界面；0 表示该组保持。程序先检查全部九轴起始状态、目标范围，再将整次运动拆成小段。

- 进给默认速度上限：`min(0.5 mm/s, 200 pulses/s ÷ StepsPerMm)`。
- 进给默认加速度上限：`min(0.5 mm/s², 400 pulses/s² ÷ StepsPerMm)`。
- 默认每段进给不超过 0.25 mm、机器人各轴不超过 200 counts；进给按整数脉冲量化。
- 每段选取共同计划时间，按三角速度曲线限制速度和加速度；先设置运动参数，再依次下发 Copley 指令，最后下发 Arduino 指令。
- 八轴都报告运动完成且处于配置容差内、进给脉冲计数等于目标、计划时间已过，才发送下一段。慢轴会让下一段等待；超时停止。
- 单独进给、分组点动和返回连接起点也经过相同的分段调度；运动期间禁止叠加新运动。

这些默认值是**拟定调试参数，待实测**。PC/CAN/USB 的顺序下发存在时延，这属于小段停止后再继续的软件协调，不是硬件同步触发或连续无停顿插补。同一小段内仍可能存在进度差；小段长度限制了命令推进量，但不等同于测得的机械同步误差。若要求连续高精度路径或严格同时起停，需进一步接入反馈、同步硬件和已标定运动学。

机器人 counts 容差默认 10。进给显示的是**已发脉冲推算位置**，没有编码器，所以无法检测丢步或堵转；软件“完成”不代表实测位置准确。

## 通信与故障处理

PC 与 Mega 使用本项目自定义 ASCII 协议（不是 Copley 或 DM542 原生协议）：`序号 命令 参数*CRC16\n`，CRC16-CCITT 初值 FFFF。反馈包含相同序号、OK/ERR、脉冲位置、使能、故障、完成、协议版本和接线确认标志。

命令：H（停止并创建本次连接坐标）、C（配置行程/脉冲速率/加速度上限）、E（使能）、S（状态/心跳）、M（绝对脉冲目标与时长 ms）、X（停止撤销使能）。运动命令超时不重发，避免重复执行；坏帧、重复序号、超限、超速均停止并锁定故障。

- PC 监控定时器标称 50 ms；Windows 消息循环、串口和 CAN 响应会影响实际周期。
- 串口命令反馈等待约 200 ms；失联会尝试停止两条链路。
- Mega 运行循环超过 750 ms 未收到有效命令便停止输出脉冲并撤销逻辑使能。它是通信软件看门狗，不是独立硬件急停或 MCU 硬件看门狗。
- 固件按非阻塞串口处理，每循环最多发一个脉冲，禁止补发高速脉冲串；计划结束后仍未完成超过 1 秒会报故障。
- Copley 位置/状态异常、进给反馈异常、限位越界、下发失败或段超时均停止本次联动。

## 源码位置

`ArduinoMotorPort.h`：Windows 串口、握手、逻辑轴 9 与 CAN 1～8 的路由。

`LinkedMotion.h`：三段映射、完整目标预检查、共同时间、分段到位屏障、失败停机。

`NineAxisUi.cpp`：参数加载、连接/停止、分组操作及九轴联动入口。

`firmware/FeedAxis/FeedCore.h`：与离线测试共享的串口协议及脉冲规划核心。

`tests/controller_tests.cpp`：离线故障和边界测试，运行结果见 `tests/test-results.txt`。
