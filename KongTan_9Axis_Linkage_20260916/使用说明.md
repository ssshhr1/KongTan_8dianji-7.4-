# 八电机 + 独立进给电机 / 叶片联动扩展版

本目录是原程序的独立副本，包含源码、Visual Studio 工程、所需的本地 CML/Ixxat/Eigen 依赖、测试和配置。原目录中的程序未被修改。

## 已实现的功能

- 机器人 1～8 号电机与另一个独立进给电机共同初始化、设置限位并使能。只有九轴全部确认成功才开放运动按钮；失败时尝试停止、撤销使能并关闭所有已初始化轴。
- 进给轴单步前进、后退、回本次连接起点；独立速度、加速度、方向、编码器坐标限位、步长和到位容差。进给轴不使用原机器人 `m_direction=-1` 的方向设置。
- 实际位置 + 驱动器运动完成事件共同判断进给到位；九轴状态读取失败、故障、越界或进给超时会触发停止。
- 原八轴手动控制和运动学保留；“八轴复位”只作用于机器人，进给轴用单独按钮返回起点。
- 软件停止和窗口退出尝试停止九轴、撤销使能、关闭总线；退出不再自动回零。初始化/关闭中途失败会继续尝试其余轴，清理失败保持错误状态，需要检查设备后重启程序。
- 原运动等待期间处理停止、退出和监控消息；机器人运动与进给手动定位互斥，避免重复下发。
- 增加逐叶片流程状态机与无硬件离线演示：对准/锁相 → 跟踪检测 → 退出检测区域 → 切换下一叶片 → 重复，最后停止。

**真实转子—机器人高速同步、编码器采样和检测设备触发尚未接入。** 本次未提供这些设备的型号/协议/参数，不能把原有逐轴定位当成高速同步。右侧按钮明确是“离线流程演示”，不会发送硬件指令。

## 从哪里打开

- 运行程序：`x64\Release\KongTan_9Axis_Linkage.exe`。
- 修改源码：用 Visual Studio 2022 打开 `KongTan_8dianji.sln`，选择 **Release | x64**。
- 实际运行配置：`x64\Release\machine.ini`，程序总是读取 EXE 同目录文件，和启动时工作目录无关。
- 工程根目录 `machine.ini` 是配置模板。构建时仅在输出目录还没有配置时复制，避免覆盖已标定参数。修改根目录模板后，需要自行同步到使用的 EXE 目录。

启动程序不会自动打开 CAN 或使能。可以直接点击右侧“演示逐叶片检测流程”，观察默认 3 片叶片的完整流程；此时机器人按钮保持禁用。演示叶片数在 INI 的 `[Demo]` 中修改。

运行环境沿用原程序：Windows x64、对应的 Visual C++/MFC 运行库，以及实机连接时所需的 Ixxat VCI 驱动和 CML 支持的驱动器。依赖文件已随工程复制；不需要引用原工程的绝对路径。

## 实机连接前填写进给轴配置

进给节点暂定 **9** 作为占位，不代表已经确认现场接线。现有 CML 封装按节点号减一索引，当前支持进给节点 **9～12**；1～8 已用于机器人。超出此范围需要改写节点映射，不能只修改 INI。

| 字段 | 含义 |
|---|---|
| `NodeId` | 实际进给驱动器 CAN 节点号，不能和机器人重复 |
| `NegativeLimitCounts` / `PositiveLimitCounts` | 驱动器当前编码器坐标系中的绝对下限/上限，不是连接起点的相对偏移，也不是毫米 |
| `VelocityCountsPerSec` | 进给速度，编码器计数/秒 |
| `AccelerationCountsPerSec2` | 加速度与减速度，编码器计数/秒² |
| `StepCounts` | 每次前进/后退的正数步长 |
| `PositionToleranceCounts` | 正数到位容差，必须小于步长 |
| `Direction` | `1` 或 `-1`，决定“进给 +”对应的编码器方向 |
| `MoveTimeoutMs` | 单次进给最大等待时间，100～600000 毫秒 |
| `Confirmed` | 上述参数核实后设为 `1` |

限位/速度/步长初值为 0，`Confirmed=0`，因此默认不能连接实机。不要直接把这些占位值当作设备参数。上电位置必须落在配置的绝对限位之内。

填写后点击“连接并使能九轴”。成功时显示 1～8 号轴与进给节点已经使能，同时记录九轴的当前编码器位置；不会自动运动。使能是软件按节点依次确认，不是同一硬件时刻的同步启动。

“回连接起点”只返回本次连接记录的位置，**不是物理原点寻零**。重新连接会重新记录起点。真正寻零方法、开关极性、丝杠导程/减速比和编码器分辨率需按设备补充。

## 后续高速联动接入位置

`BladeSequence.h` 中的 `ITrackingBackend` 是后续硬件适配接口：

| 接口 | 实际控制器需要完成的工作 |
|---|---|
| `Prepare(run, blade, angle)` | 选定叶片，准备转子目标相位及机器人起始位姿，建立主从跟踪条件 |
| `StartTracking(run, blade)` | 启动硬件同步轨迹和检测采集；由控制器处理高速跟踪闭环 |
| `Read(feedback, now)` | 返回当前命令的锁相、相位误差、采集完成、退出完成、分度完成和故障反馈 |
| `Retract(run, blade)` | 停止采集并退出检测区域，完成后才返回 `retracted=true` |
| `Index(run, nextBlade, angle)` | 确认已退出后分度至下一叶片，完成后返回 `indexed=true` |
| `Stop()` | 同时停止转子、机器人及采集，清理本次轨迹/触发任务并报告结果 |

适配器必须满足以下契约：

1. 接收新命令时清除旧完成标志。所有反馈携带当前 `run` 和零基 `blade`，不能把上一轮或上一叶片的完成事件用于下一片。
2. 状态机与适配器使用同一单调时间基准，或者在适配器中转换时间。反馈过期、未来时间、时钟倒退、失锁和相位误差过大会进入故障并请求停止。
3. `prepared` 只在轨迹和起始条件确实就绪时置位；`scanDone` 来自实际采集完成，`retracted` 来自机器人已退出的确认，`indexed` 来自转子实际分度到位，不能用固定延时替代。
4. 硬件适配器负责编码器主轴、机器人轨迹、采集触发的时钟同步/缓存/插补，以及控制器侧看门狗。接口调用应迅速返回，Windows 定时器只做流程监控。
5. 当前演示按等间距叶片计算未取模的目标角度：`首片角 + 方向 × 叶片索引 × 360/叶片数`。非等间距、跳片或不停转切换需要替换目标角表/相位窗口及对应控制器策略。

接入时替换 `NineAxisUi.cpp`/对话框成员中的 `DemoBackend`，再按实际机器人运动学提供多轴同步轨迹。当前六轴逆解仍只控制 1～6 号轴，7/8 号轴保留原手动控制；没有凭空加入进给轴、7/8 轴与转子的几何模型。当前软件九轴不包含独立转子驱动器。

需要提供：进给轴节点及行程/单位换算；转子驱动方式、节点/协议与编码器；机器人控制器或当前八轴驱动器的同步能力；叶片数量、相位基准、检测轨迹与目标转速；检测设备的触发和完成接口；允许的跟踪误差与退出条件。

## 验证与边界

离线测试入口为 `tests\controller_tests.vcxproj` 和 `tests\bin\controller_tests.exe`，使用模拟端口，覆盖 27 组测试：配置校验、全部九轴使能顺序、任意轴使能/限位失败回滚、进给方向/越界/到位/超时、反馈丢失、叶片流程顺序、反向分度、旧反馈、失锁和停止等。测试不连接 CAN。

Release 构建关闭了工程自身的 `/GL`，以兼容现有预编译 CML 库的编译器版本。源码中的旧 Eigen 索引类型警告及 CML 缺少调试 PDB 的链接警告不代表已验证硬件兼容性。

本次完成的是编译和离线逻辑验证，未进行真实窗口视觉检查、CAN 联机试验或高速跟踪精度测试。100 ms 窗口定时器和软件停止不是实时安全控制；串行 CAN 请求、旧逆解计算和模态提示仍可能延迟界面响应。设备的硬件停止、限位、抱闸及看门狗按实际系统实现。

`_work` 是本次生成过程记录，实际工程与 EXE 不依赖它；不要重新运行其中的一次性复制脚本覆盖已修改的源码。
